Access API documentation

Use the versioned REST API to load a lesson, discover accessible media, or retrieve portable downloads. The public demo uses allowlisted lessons and fictional career data. ALX authentication and protected course integration are pending.

Make your first request

Start with the Savanna lesson manifest. The public lesson reads require no credentials. For these examples, run the repository’s FastAPI service on port 8000. On a hosted install, replace the origin with the URL of this service.

curl --fail-with-body 'http://127.0.0.1:8000/api/v1/lessons/alx-transforming-africa/manifest?version=1'
  • Read the live Savanna manifest JSON.
  • Read the live English transcript JSON.
  • Read the live download listing JSON.

Check that schema_version is supported and lesson_id and content_version match your request. Keep the explicit version in subsequent requests. For optional media and downloads, follow the returned URL fields and handle missing entries in the UI.

Lesson endpoints

Every operation below uses GET under /api/v1/lessons/{lesson_id}. version is a positive integer and defaults to 1. Demo fixtures include alx-transforming-africa, demo-learning-plan, and w3c-colors-with-good-contrast.

/manifest?version=1
Returns the course and lesson revision, accessible content, media links and review states. Fields such as media and optional asset URLs can be null. A timed segment includes start and end times in seconds.
/transcripts/{language}?version=1
Returns ordered segments with stable IDs from the source transcript or the selected caption track. Discover available languages in the media manifest. The status field preserves source and translation review labels; machine-translated transcripts are not human-reviewed. Missing languages and lesson versions return 404.
/media/{kind}?version=1
Returns WebVTT, MP4, or MP3 according to the asset. Savanna lists captions, captions-am, captions-om, and captions-ti. The translated tracks are labeled machine-translated-review-pending. The W3C lesson provides described-video and described-audio; audio-description is an alias for its described MP3. The ALX introduction has no described recording and returns 404 for those kinds. Follow optional asset URLs in the manifest. File-backed media supports byte ranges.
/offline-player?version=1
Downloads a self-contained HTML player with this lesson’s media, caption languages and searchable transcripts. Open the saved file in a browser.
/offline-video/{edition}?version=1
Returns an MP4 download when the requested standard or described rendition is built. Use its advertised URL in the manifest when present.
/exports?version=1 and /downloads/{format}?version=1
The listing returns the available format, URL, byte count, SHA-256 checksum, and media type. Download the listed URL and compare its bytes to the listed checksum. The ZIP also includes a manifest of its files. The W3C fixture adds PDF and BRF prototypes with verification pending.
/signing-manifest?lang=ethsl&version=1 and /signing-assets/{filename}
Inspect the requested language and each segment’s review state. Follow asset URLs included for approved entries. The separate public ASL animation preview in Savanna is a labeled prototype for selected concepts.

Errors and caching

  • 304 on a manifest means reuse the saved representation. Send the returned ETag as If-None-Match on a subsequent request.
  • 404 means the requested lesson, revision, language, or asset is unavailable. Show the user an alternative when the manifest offers one.
  • 422 means a parameter or request body failed validation. Check the OpenAPI contract before retrying.
  • 429 on the optional speech service means respect Retry-After when present. The career demo also offers typed controls.
  • 500 or 503 means a server error or unavailable service. Provide a retry and preserve the user’s local context.

Application errors use the following envelope. The correlation ID is generated per request. Use it when reporting a failure.

{
  "error": {
    "code": "not_found",
    "message": "This resource is unavailable.",
    "correlation_id": "example-id"
  }
}

Embed in a host page

  1. Open the installation demo, select a lesson, and install the component. The example supplies the versioned module URL and SHA-384 integrity value from the built release.
  2. Copy the snippet to your host. It supplies api-base, lesson-id, content-version, and a fallback download link. Use HTTPS for a hosted installation.
  3. For a different origin, configure the API’s exact ACCESS_ALLOWED_ORIGINS and allow the component scripts, API calls, and media in the host’s Content Security Policy. Public lesson fetches omit credentials.
  4. Listen for alx-media-ready with lessonId and contentVersion. Handle alx-media-error with the code and lessonId. An alx-media-download event reports the requested format and status requested.

Keep one released bundle and its chunks together. The demo installation generates an integrity value for its current build. Freeze those assets before distributing a production embed.

Career and privacy demos

  • Public fictional job data and a JobPosting JSON example power the career demo.
  • Fictional certificate verification returns a demo status and optional course name and date. An unknown identifier returns 200 with status unknown.
  • Optional Amharic speech catalog advertises availability. Speech POST requests from permitted origins require validated JSON and a configured private worker. Typed job controls are available without the worker.
  • The privacy demo uses separate same-origin session cookies and checks CSRF for authenticated mutations. Use its demo UI for session and privacy actions. See OpenAPI for operation details.
